# Usage Statistics & Metrics Generation for NeDRex-Web, Drugst.One, EpistasisDiseaseAtlas, and DIGEST

This project processes apache web service access logs to generate usage statistics, unique visitor counts, and behavioral metrics for various tools (Drugst.One, NeDRex, etc.) after cleaning the logs form easily detectable bot-based requets.

## Workflow Overview

The pipeline (`run_all.sh`) executes the following steps:
1.  **Combine**: Merges archived and current logs from multiple sources.
2.  **Separate & Pseudonymize**: Splits combined logs into tool-specific files and renames minor apps for privacy.
3.  **Clean**: Filters out bots, scrapers, and "fake" traffic.
4.  **Statistics**: Generates monthly hit/unique visitor plots.
5.  **Additional Statistics**: Computes specialized metrics for dissertation reporting using bash scripts.


6. (**Log Injection**: Latest run_all.sh.log is added to the bottom of this README.md for transparancy)

## Requirements

*   **Python 3.11+**: The scripts use the built-in `tomllib` (available since 3.11). For older versions, you may need to install and alias `tomli`.
*   **Python Libraries**:
    *   pandas
    *   matplotlib 

## Filtering Logic

To ensure high-quality data, two layers of filtering are applied:
*   **Regex Filter**: Removes known bots (Google, Bing, etc.) and headless clients (curl, python-requests).
*   **Behavioral Filter (`fake_bot.ips`)**: Identifies IPs that access the standalone landing page but never load the required JavaScript plugin. These are categorized as non-human scrapers and excluded.

## Configuration

Control the pipeline via `config.toml`. Original config.toml cannot be provided due to pseudonymization information of unrelated tools. `config.dev.toml` gives an example of the structure:
* `archive_source_dir`: Absolute path to the /apache_log_archives/ folder. In our case, this one contains three folders, manually named as `old`, `middle`, and `current`, which are subsequently combined into one large log file by the first processing step. 
* `toolname_map`: Map request paths to internal tool IDs.
*   `toolnames`: Final display names/pseudonyms.
*   `exclude`: Directories to ignore, e.g. statistical endpoints, document servers, out-of-service pages, ...

## Folders
*   `logs/`: Contains the merged logs, separated into multiple folders by endpoint (e.g. `/drugstone`) with possible multiple log files per directory (e.g. `backend-access.log`, `website-access.log`). Due to GDPR regulations around IP addresses, this directory cannot be shared publicly. 
*   `output/`: Contains `.png` figures for Hits and Cumulative Uniques.
*   `results/`: Contains raw `.ips` and `.urls` files for verification. Due to GDPR regulations around IP addresses, this directory cannot be shared publicly.

## Usage

```bash
bash run_all.sh
```
or to update the run_all.sh.log
```bash
bash run_all.sh > run_all.sh.log
```
